# 统一入口与参数

命令：`node scripts/render-poster.cjs config.json output-directory`。

```json
{
  "variant": "mint",
  "originalText": "谁能凭爱意将富士山私有",
  "text": "谁能凭爱意将富士山私有。",
  "lines": ["谁能凭爱意", "将富士山私有。"],
  "sourceType": "lyrics",
  "author": "确认展示的作者姓名",
  "workTitle": "作品名称",
  "credits": {"lyricist": "已核实词作者", "composer": "已核实曲作者"},
  "sourcePrefix": "",
  "backgroundText": ["陈奕迅", "富士山下"],
  "emphasis": []
}
```

红黑版把 variant 设为 darkroom，并增加 photo（相对于配置文件的照片路径）。

| 参数 | 说明 |
| --- | --- |
| outputName | 可选输出文件名主体，不含路径分隔符；多张同任务海报用编号和短名保存到同一个目录。省略时仍输出 poster.png、poster.html、recipe.json |
| variant | 必填，darkroom / mint，先由用户选择 |
| originalText | 原始用户输入，保留繁体等原样，校验时按 scriptMode 转换后比较 |
| normalizedOriginalText | 由渲染器计算的校验文本，不需手动填写 |
| scriptMode | 默认 simplified：显示文字自动转简体；仅明确要求保留原文字形时用 preserve |
| text | 用户确认的正文；默认补齐符合完整句意的必要标点，必填 |
| punctuationPolicy | 默认 semantic，正文须有必要语义标点；明确无标点时用 none，逐字保留时用 verbatim 且 scriptMode: preserve |
| punctuationExceptionConfirmed | 仅用户明确要求上述例外时为 true，标记本身不构成授权 |
| punctuationMode | 旧配置兼容字段，不代表用户已要求无标点；默认正文按句意有标点，视觉换行不强制行末标点 |
| lines | 推荐必填，由制作助手按语义安排；省略时用 text 中已有换行。禁止空行，合并后必须等于正文 |
| author | 已核实且经用户确认的作者姓名；歌词作品名称用 workTitle，词曲信息用 credits；兼容旧配置的合并字符串 |
| sourceType | lyrics / quote，决定歌词或名言来源格式 |
| workTitle | 歌词作品名称；主行绘制为“作者《作品名称》” |
| sourceMedium | 名言实际来源媒介，如文章、视频、书籍、演讲、采访 |
| sourceTitle | 名言已查证的实际来源标题；次行绘制为“媒介《标题》”，不得猜测 |
| credits | 可选对象，lyricist、composer 为已核实作者字符串；绘制较小的第二行“作词：…  作曲：…” |
| sourcePrefix | 旧配置兼容的来源主行前缀；现在默认空，新制作不自动添加“——” |
| backgroundText | 浅绿版背景大字，零至两行字符串，由作者、作品名提取。单行拉伸到1200×1200，两行各拉伸到1200×600，按字形实际边界独立缩放横纵轴 |
| emphasis | 按语义建议或由用户指定，在确认稿正文下方用大号标题单列；确认后填写准确词组列表。相对字号 1.55，固定字距不变 |
| photo | 红黑版必填，用户照片或按确认风格生成的无文字底图路径；浅绿版不用 |
| focusX / focusY | 红黑版裁切焦点 0..1，默认 0.5 |
| backgroundTreatment | 红黑版底图处理：preserve 保留生成底图原色，只叠加正文、来源与 Logo，忽略亮度、对比、蒙版和颗粒参数；redblack 为传统照片处理。省略兼容 redblack；生成底图必须显式设 preserve |
| opacity | 红黑蒙版透明度，0..1，默认 0.85 |
| brightness / contrast | 红黑版照片亮度、对比度，默认 1.05 / 1.2 |
| grainOpacity | 红黑版颗粒强度，0..1，默认 0.23 |
| brand | 默认原图 Logo；false 隐藏 |
| font | 默认留空，使用又又意宋；只有用户明确更换字体时填写 TTF/OTF 路径，可 gzip 压缩 |
| fontChangeConfirmed | 仅用户已明确授权更换字体时设为 true；标记本身不构成授权 |
| layout | 默认顶部正方形；long 为用户要求长文同图；legacy 为保留旧暗房作品坐标 |

两版正文块均按实际字形总高度在正文区域内垂直居中，上下留白均衡，取消固定 40 px 顶部留白。左右保持原左对齐，四周至少 8 px。来源位置不变。

两版正文和强调字的固定字距统一为 **-45 px**，字号变化时不变，不允许逐行覆盖。来源字距仍使用署名版式的独立参数。

固定字号适配范围为 24..600 px，根据含强调词的全部可见字形、固定字距和按小字可见边界建立的视觉间距，整行大字局部协调选择最大可用基础字号。不要传入逐行字距覆盖。输出 recipe.json 包含实际字号、各行字形边界和来源顶部位置，可用于排版检查。

输出 poster.png、poster.html、recipe.json。HTML 以相对路径引用成品目录下的 `_assets/`；相同字体和图片按内容复用，不重复内嵌。离线打开、移动或分享需保留 HTML 和 `_assets/` 的相对位置，可打包整个成品目录。PNG 可单独使用。PNG 与 HTML 共享文字坐标，但字体抗锯齿与混合细节受渲染器影响，不保证逐像素一致。

示例展示语义标点，不要求短句一律两行。实际按文意、完整词组及可用面积共同确定行数，不能为填满版面强行断开词组。

## 歌词与名言来源版式

歌词第一行“作者《作品名称》”，第二行“作词：姓名　作曲：姓名”；名言第一行“作者”，第二行标明具体来源媒介和标题，例如“文章《标题》”“视频《标题》”。分类标签“歌词”“名言”不印在海报上，不默认添加“——”。名言必须核实实际标题，查不到时在文字确认阶段说明，不用猜测的标题生成。

两行沿用 `source-layout-reference.jpg` 的字号层级及右对齐关系，主行默认 77.77778 px，次行默认 55.55556 px，可见空隙 14 px，右边界 x=1190，主行上沿贴正文框下沿。来源字距 -4.666667 px，各行超宽独立缩小，不拉伸。`recipe.json` 的 `sourceRows` 记录文字、角色和边界。长文启用两行来源时正文止于 y=1360，否则 y=1430。

名言配置示意（姓名、标题须先查证确认）：
```json
{"sourceType":"quote","author":"作者姓名","sourceMedium":"视频","sourceTitle":"已核实的视频标题"}
```

## 大小字混排行距

行距按普通字号小字的视觉节奏安排，14 px 为小字间参考空隙。大字的高度不决定整块行距，也不因大字碰撞自动扩大所有行的基线间距。数值上的等距不等于视觉疏密一致；需要按实际字形协调强调大字的位置，保持小字阅读节奏。出现碰撞优先协调大字位置、字块排布或换行，必要时整体小幅缩小字号并保持强调比例；修改已确认断行或强调须重新确认文字。

实现已更新：混排使用小字可见边界作为相邻行间距锚点；整行均为强调文字时使用实际字形边界局部协调。取消碰撞时自动增大全局行距。碰撞无法解决时拒绝渲染，先调整位置或换行，不暗中扩大全局行距。`recipe.json` 的 `lineSpacingMode` 为 `optical-small-word-anchors`，记录各行 `anchorTop`、`anchorBottom`、`anchorMode` 和实际 `baselineSteps`。

## 断行确认与规则调整阶段

长短行失衡时，先在不破坏词组和语意的自然位置拆开过长行，比较三行、四行等方案，避免两行短句或一条长行压小字号造成大面积空白。保留转换后完整词组、文字顺序和含义，视觉换行不意味着断句，不因换行补逗号；确有语义需要的标点才提出，并放在文字确认稿中。以正常 Markdown 展示正文实际断行，在正文下方注明“放大词（海报中为普通字的 1.55 倍）：”，再用三级标题单列词组；没有强调时写“放大词：无”。确认后再转成配置；确认用的标签、标题符号和分隔点不写入 text 或 lines。讨论或修改 Skill 时仅更新规则及确认稿，不自动渲染。

视觉换行不强制行末标点。例如 `lines: ["你献出了", "十寸时和分，", "可有换到", "十寸金？"]` 是两句话的四行视觉排版，第一行和第三行不加逗号。

混排行的强调词与上一行实际字形发生局部碰撞时，脚本可只协调该强调词的纵向位置，保持小字锚点及其他行位置；`rendered[].emphasisOffsets` 记录实际偏移。不靠把整块字号缩到过小来掩盖碰撞。

## 以强调词位置为目标的可选分行

这类分行的核心是让放大的词组位于其所在行的开头，并让相关强调词可以集中成块。为此可以调整前面的分段和换行，不要求换行发生在逗号或句尾。不是按固定字数分行，也不要求各行字数相同或接近；完整词组、原文顺序和阅读效果优先。

“行首”指每行的开头，不是整张正文第一行。这是可优先比较的排法，不强制每张作品采用；还可比较大字独立一行、连续两行或混排等方案。最终断行和强调词仍先展示给用户确认，再生成图片。

## 红黑版生成底图的主体构图

完整画布为 1200 × 1600；顶部 1200 × 1200 是主体图像与正文共用的 1:1 框。生成提示必须要求核心主体完整落在这个框内，并与大字协调。主体可以在框内灵活安排，不固定居中，不以把主体下沉到署名区来制造文字留白。底部 400 px 仅延续低细节背景或纹理，承载来源与 Logo。

非写实试作可将原句与用户确认的版画风格提示交给生成模型，自行选择意象；没有指定主体时不预设人物或物件。保留先确认文字与方向再出图的流程。

## 简体转换与缺字检查

默认将正文、断行、强调词、作者、作品名、来源标题、词曲署名和背景字转换为简体。原始 originalText 和照片、字体、输出文件名等路径字段不转换。转换实现使用 [opencc-js](https://github.com/nk2028/opencc-js) 的繁体到简体模式（包含台湾字形归一，以正确处理“活著”等语境），不进行地区词汇本地化。若跨行词组导致分别转换的 lines 与整句 text 不一致，应基于完整句子重新确认断行，不随意改词。

确认稿先展示简体，再写入配置；渲染器也做相同转换。originalText 校验允许此简繁转换，继续保留字词顺序和已有标点校验。明确保留繁体时传 scriptMode: preserve。

简繁转换不影响字体选择。渲染器检查字体 cmap 是否包含实际显示字符，缺字明确报错，不交给系统字体回退。正文与来源仍用又又意宋，背景字仍用京華老宋体。

## 验收报告

正式渲染自动写入实际字号、字体指纹、逐字坐标及成品指纹，并调用 `scripts/verify-poster.cjs` 生成验收 JSON。自动通过后仍需实际打开 PNG 看图；完成后用 `--visual-reviewed` 标记，不能直接把程序通过当作视觉通过。修改边界、优先级、验收命令和异常处理见 [验收说明](acceptance.md)。

## 默认语义标点

每张图的正文应有符合完整句意的标点，视觉换行不自动添加标点。只有用户明确要求无标点或原文逐字保留时例外；例外在文字确认说明中注明，不从原文没标点、旧配置标记或保留断行推断。

先给完整句子补必要标点，再确定 lines。原文无标点时，允许补适合句意的逗号、句号、问号、感叹号等，不能借标点改词。程序不能判断标点是否符合语义，因此文字确认和看图验收必须检查；渲染器不自行插入任何标点。

生成红黑版底图前阅读 [红黑版底图规则](red-background.md)，按完整原句、半抽象风格、指定主红色与顶部 1:1 构图生成，不预设每句共用的固定主体。
