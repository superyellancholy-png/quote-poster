# 验收与异常处理

## 修改边界

常规海报制作仅改配置与素材，统一执行 `scripts/render-poster.cjs`。不复制、改写或另写临时脚本，不换字体或改固定参数掩盖问题。主入口每次生成记录字体文件指纹、输入配置指纹、实际字形坐标及字号、PNG/HTML 指纹；验收器核对正式入口与当前配置，避免旧产物或临时入口冒充本次结果。

用户明确授权程序修复或技能维护时，可以修正式脚本；先定位原因并保留最小复现，验证原来正常的例子及失败例子，再同步代码和版本。不能因一次局部排版不理想自行扩展为改模板。

## 取舍顺序

1. 保持用户确认的正文、强调与署名（按已确认的简繁模式），来源须可靠；确认内容不能暗改。
2. 保持约定字体、字距和强调比例、小字行距、不越界且无跨行碰撞。
3. 在上述约束内保证完整词组、自然断行与阅读节奏。
4. 再提高可用字号、改善填充与背景配合；“填满”不是改字距、扩大行距、改字体的理由。

无法兼顾时，报告具体冲突、实际字号及留白情况。可以提出重新分行、调整强调或拆图的方案；涉及确认内容的改变仍先给用户看新版文字。不能输出一个过度缩字的结果而宣称已达到排版要求。

## 程序验收

统一版渲染结束后自动执行：

```sh
node scripts/verify-poster.cjs config.json output-directory
```

有 `outputName` 时生成 `<outputName>_验收.json`；默认生成 `verification.json`。自动项检查：

- 正式渲染入口及本次配置指纹，PNG/HTML 与参数文件配对。
- PNG 1200×1600；按当前简繁模式核对文字、断行与强调词；检查正文有标点或配置记录明确例外。标点是否符合句意仍须人工判断。
- 实际 HTML 引用字体与原字体字节一致；核对字体字形覆盖，缺字不回退系统字体。
- 对实际字形字号及横坐标检查正文 −45 px 字距、来源独立字距及 1.55 倍强调。
- 根据实际字体重新测量字形边界，独立检查跨行碰撞、越界、居中和上下留白，不只相信 `collisionChecked` 字段。
- 检查小字锚点行距、署名内容与位置、原 Logo 素材与位置、共享素材引用。

字体覆盖检查不能证明字体的许可范围。来源字符串与配置一致不能证明来源真实。`fontChangeConfirmed` 只是配置记录，模型仍须从用户指令取得换字体授权。

正文面积偏小会产生告警和实际占用率，不自动等同于视觉失败；模型须查看是否因碰撞被迫过度缩字，无法符合目标时报告冲突。不能为了消除告警擅改文字。

## 看图检查与交付

程序报告最初标为 `needs-visual-review`，不算交付完成。实际打开最终 PNG，逐项检查：

- 又又意宋字形风格是否保持，有无系统字体、方框或缺字。
- 简繁、文字、强调和来源与确认稿一致，出处已经查证；每张正文都有符合完整句意的标点。视觉换行没有额外制造停顿；无标点或逐字保留例外确由用户明确要求，并已在确认说明中注明。
- 行距、断行、视觉疏密、字号与整体填充是否自然，有无孤字或孤立标点。
- 主体构图、背景与文字是否协调，红黑生成底图的核心主体是否位于顶部 1:1 框内。
- 署名和 Logo 是否清晰完整。

全部满足后再执行：

```sh
node scripts/verify-poster.cjs config.json output-directory --visual-reviewed
```

报告 `automaticStatus: passed` 且 `deliveryStatus: reviewed` 后才按当前规范交付。标记表示已实际看图，并不保证视觉判断永远正确；禁止未看图就标记。程序失败时不能用视觉标记盖过失败。

验收器适用于统一版和 long 布局。legacy 仅用于用户明确要求保留已有旧版坐标的任务，其不同强调比例与几何规则不能冒充统一版验收通过；不能切换 legacy 来绕过新海报异常，应按确认的旧版要求单独检查并说明范围。

## 异常定位

先检查：字体路径/覆盖 → 繁简及原文一致性 → 强调匹配 → 实际行宽、字号和字形边界 → 跨行碰撞 → 行距、留白和来源区域。配置错误用配置修；程序缺陷走正式修复。原始素材与旧版产物保留，避免失败产物被误认为新成品。
